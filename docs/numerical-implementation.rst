Discretization and algorithms
-----------------------------

DG basis functions
^^^^^^^^^^^^^^^^^^

The discontinuous Galerkin fields are stored by their coefficients with respect to a
hierarchical basis that is orthogonal on the reference element :math:`[0,1]^2`.
With :math:`X = x-1/2` and :math:`Y = y-1/2`, the basis functions are, by index (the
number of components of a field determines the space):

====== ======================================== ========================
Index  Basis function                           Space (components)
====== ======================================== ========================
0      :math:`1`                                dG0 (1)
1, 2   :math:`X`, :math:`Y`                     dG1 (3)
3      :math:`XY`                               dQ1 (4)
4, 5   :math:`X^2-1/12`, :math:`Y^2-1/12`       dG2 (6)
6, 7   :math:`Y(X^2-1/12)`, :math:`X(Y^2-1/12)` dG2+ (8, CG2 stresses)
8      :math:`(X^2-1/12)(Y^2-1/12)`             dQ2 (9)
====== ======================================== ========================

The mixed term :math:`XY` precedes the pure quadratic terms such that the first four
components span the bilinear space dQ1. The tables of basis function values used in the
code are generated by the Python scripts in ``dynamics/codegeneration``.

.. note::

   Before the introduction of the LDG momentum discretization, the components 3, 4, 5 were
   :math:`X^2-1/12`, :math:`Y^2-1/12`, :math:`XY`. Fields with only 1 or 3 components
   (``DG1`` dynamics with CG1 stresses) are not affected. Fields with 6 or 8 components
   (``DG2`` dynamics) in restart or output files written with the old ordering can be
   converted with

   .. code::

      python3 scripts/convert_dg_basis_order.py old_restart.nc new_restart.nc

   The option ``--reverse`` converts back to the old ordering.


LDG discretization of the momentum equation
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The dynamics module ``Nextsim::LDGMEVPDynamics`` discretizes the momentum equation with the
local discontinuous Galerkin (LDG) method instead of continuous (CG) velocities. Velocity,
strain and stress are discontinuous in the same space (CMake option ``LDGVelocity``), the
system is solved with the mEVP iteration. In each sub-iteration the stress is updated, then
the velocity is obtained from :math:`((1+\beta)\rho_{ice} M_H + \Delta t J) u = F` with
the jump penalty :math:`J` by a matrix-free preconditioned CG method, and finally the strain
is computed from the velocity with the LDG fluxes
:math:`\hat u = (1/2+a) u^- + (1/2-a) u^+`, :math:`\hat\sigma n = (1/2-a)\sigma^- n +
(1/2+a)\sigma^+ n - b/h [[u]]`. The ice and snow fields are transported with the full DG
velocity (no projection onto the advection space).

Boundary conditions: :math:`u=0` on edges between ice and land, the outer boundary of the
mesh is free (:math:`\sigma n = 0`). The current implementation supports Cartesian
grids only, without periodic boundaries, MPI or Kokkos.

Additional configuration options (besides those of ``MEVPDynamics``):
``LDGMEVPDynamics.ldg_a`` and ``LDGMEVPDynamics.ldg_b`` (flux parameters :math:`a`, :math:`b`),
``LDGMEVPDynamics.alpha`` and ``LDGMEVPDynamics.beta`` (mEVP parameters),
``LDGMEVPDynamics.pcg_tolerance`` and ``LDGMEVPDynamics.pcg_max_iterations``,
``LDGMEVPDynamics.replacement_pressure``.
